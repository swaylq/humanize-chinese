## 一、现状诊断：当前改写端的四个核心问题

下列例子全部来自 [dev/reports/semantic_check_articles.md](file:///d:/working/0001/humanize-chinese-dimension/dev/reports/semantic_check_articles.md) 的真实改写输出（Adaptive 模式），非杜撰。

### 1.1 不合语义的超短句注入（最严重）

[scripts/rewrite_operations.py](file:///d:/working/0001/humanize-chinese-dimension/scripts/rewrite_operations.py) 第 69–74 行的 `_FRAGMENTS` 词表：

```python
_FRAGMENTS = [
    "真的。", "但没用。", "就这样。", "未必。", "看情况。",
    "难说。", "不一定。", "谁知道呢。", "不好说。", "其实不然。",
    "未必如此。", "未必有效。", "未必能成。", "没什么大不了的。",
    "也是奇怪。", "也正常。", "无所谓了。", "算了。",
]
```

这些碎片被 `burstiness_engineering`（第 96–172 行）和 `fragment_injection`（第 179–213 行）**机械插入**，完全不考虑上下文。真实后果：

| 案例 | 原文片段 | 改写后 | 问题 |
|------|---------|--------|------|
| 案例 2（医学论文） | "重点分析其在细胞代谢、增殖及凋亡中的角色" | "重点分析其在细胞代谢、。**真的。**增殖及凋亡中的角色" | 碎片插进了名词短语中间，断开了并列项 |
| 案例 3（爷爷叙事） | "在这个世界上，每个人都有自己的邻居" | "在这个世界上。**谁知道呢。**每个人都有自己的邻居" | "谁知道呢"与温情的开头完全冲突 |
| 案例 3（爷爷叙事） | "鼓励和支持" 后 | "**没什么大不了的。**" | 把对爷爷的怀念轻化为"没什么大不了"，情感错位 |
| 案例 5（童年回忆） | 结尾"那些被我们忽略的小确幸" | "...**就这样。**" | 用"就这样"截断哲理收尾，仓促 |

**根本原因**：
- `_FRAGMENTS` 是**单一混杂词表**，含 hedging（未必）、评论（也是奇怪）、终结（就这样）、消极（算了）等多种语用功能，插入时不分类。
- 插入位置只看句长（`> 25 字`）和前一个碎片距离，**不看语义、情感、语体**。
- `burstiness_engineering` 的 `_find_natural_split` 只在逗号/顿号处拆，但拆完后在拆点插入碎片，导致"细胞代谢、。真的。增殖"这种断词。

### 1.2 标点符号滥用（尤其是省略号）

[scripts/rewrite_operations.py](file:///d:/working/0001/humanize-chinese-dimension/scripts/rewrite_operations.py) 第 451–458 行 `punctuation_humanize`：

```python
# 3. 在适当位置加省略号
if result.count('……') == 0 and rng.random() < intensity * 0.3:
    paras = result.split('\n')
    if paras:
        last_para = paras[-1].rstrip('。')
        if len(last_para) > 50:
            paras[-1] = last_para + '……'
            result = '\n'.join(paras)
```

问题：
- **触发条件只是"长度 > 50 + 随机命中"**，完全不看末句语义是否属于"未尽/沉思/留白"。
- 省略号被加到**末段末句**，但末句常常是结论性陈述（"势头不错……""确保了实验的可靠性……"），语义上应当收束而非延宕。
- PR 案例中 AI 三段式末尾"势头不错……"、学术案例末尾"确保了实验的可靠性……"都是反面典型。

### 1.3 同义词替换误伤（无词义消歧）

PR 文档已记录：baseline/old_dim 把"**数据隐私**"误替换为"**数额隐私**"或"**多寡隐私**"。根因是 `_VOCAB_REPLACEMENTS`（第 467–505 行）的候选词不区分词义，"数据"在"数据隐私"里是 data，而"数额/多寡"是 quantity，属于不同义项。

类似风险词：分析、研究、系统、机制、过程、表现……这些都是高频多义词，盲目替换会出 bug。

### 1.4 "攻击式"改写的哲学问题

当前自适应路由（[dimension_router.py](file:///d:/working/0001/humanize-chinese-dimension/scripts/dimension_router.py)）的逻辑是：**检测端发现哪个维度分数高 → 路由到对应操作 → 强制降低该维度**。这本质上是把检测器当 oracle，对文本做对抗攻击。

文献里这类方法叫 **Adversarial Paraphrasing**（NeurIPS 2025, Cheng et al.）或 **AuthorMist**（arXiv 2503.08716）。它们确实能降分，但论文自己也承认存在 **quality tradeoff**：
- AuthorMist 报告语义相似度 0.94+，但这是用 LLM 做语义保持；纯规则方法做不到。
- HKU 2025 研究（*Semantic Effects of AI Humanizers*）指出：**commercial humanizer 普遍存在 semantic drift**，在学术写作场景即使微小语义偏移也会误传关键发现。

**项目初衷是"去 AI 味"而非"对抗检测器"**。当前 Adaptive 模式把"降低 LR 分"作为唯一目标，导致操作不惜破坏语义来换分（案例 2 把"增殖"和"凋亡"用"真的"隔开就是典型）。这与 README 宣称的"帮你更像人写的，不是反检测魔法"自相矛盾。

## 二、理论支撑：相关研究综述

### 2.1 话语连贯性 — Centering Theory（中心理论）

**来源**: Grosz, Joshi & Weinstein (1995), *Centering: A Framework for Modeling the Local Coherence of Discourse*, ACL Journal [J95-4004](https://aclanthology.org/J95-4004.pdf)

核心观点：
- 每个语篇有一个局部"中心"（center，通常是当前最显著的实体）。
- 相邻句之间的"中心转移"分四类，**连贯性优先级递减**：
  - **Continue**（中心延续）：相邻句讨论同一中心 → 最连贯
  - **Retain**（中心保持）：中心仍在但不是最显著 → 次连贯
  - **Smooth-shift**（顺畅转换）：中心换了，但新中心是当前句最显著实体 → 可接受
  - **Rough-shift**（不顺畅转换）：中心换且不是最显著 → **最不连贯**

**对项目的启示**：
- 当前 `_FRAGMENTS` 插入"谁知道呢""也是奇怪"这类无实义碎片，相当于在没有中心转移语义的情况下强行制造 **Rough-shift**，破坏 Centering Theory 意义上的局部连贯。
- 正确做法：碎片应当只在与前句构成合法 discourse relation（如 Elaboration / Contrast / Cause）时插入，并且最好以 **discourse marker**（话语标记语）形式出现，而不是孤立评论。

### 2.2 话语标记语（Discourse Markers）

**来源**:
- Frontiers in Human Neuroscience 2024, *On the influence of discourse connectives on the predictions of humans and language models* [10.3389/fnhum.2024.1363120](https://www.frontiersin.org/journals/human-neuroscience/articles/10.3389/fnhum.2024.1363120/full)
- Wiley 2025, *Multiword Discourse Markers Across Languages* [10.1111/ijal.12755](https://onlinelibrary.wiley.com/doi/10.1111/ijal.12755)

核心观点：
- Discourse connectives（and / but / because / however …）明示相邻话语单元的语义关系（temporal / contingency / comparison …）。
- 人类在事件知识足够时可省略 connective（隐式关系），但**省略不等于随机插入无关词**。
- 中文里"另外""不过""说到底""再说""其实"等都是 DM，承担衔接功能。

**对项目的启示**：
- 与其插"真的。""未必。"，不如插"**话说回来**""**换个角度看**""**不过话又说回来**"这类有衔接功能的 DM。
- DM 至少能让读者解析出 Contrast / Elaboration 关系，不会出现"谁知道呢"这种悬空评论。
- `_VOCAB_REPLACEMENTS` 里已经有部分 DM 替换（"首先"→"先说"），但 `_FRAGMENTS` 没有走这条路。

### 2.3 语义漂移（Semantic Drift）

**来源**: HKU FYP25047, *Semantic Effects of AI Humanizers: Evaluation and Improvement Strategies* [项目计划书](https://wp2025.cs.hku.hk/fyp25047/wp-content/uploads/sites/48/FYP25047_Detailed-Project-Plan-1.pdf)；Ji et al. 对 semantic drift 的 NLP 定义。

核心观点：
- Paraphrasing 本应保持意义，但 style transfer 方法常常**无意扭曲输入的语义属性**。
- 在学术写作场景，**微小语义偏移也会误传关键发现**。
- 评估 humanizer 不能只看检测率下降，必须同时度量 **paragraph-level semantic similarity**。

**对项目的启示**：
- 当前 `dev/semantic_check.py` 已有简易完整性检查（len_ratio / char_overlap / word_overlap / para_ratio），但**没有句子级语义相似度**，无法捕捉"数据隐私→数额隐私"这种字符重叠高但语义错位的 case。
- `best-of-n` 候选筛选目前只看 LR 分，应当加入**语义保持约束**（候选与原文的语义相似度低于阈值则丢弃）。

### 2.4 词义消歧（WSD）

**来源**:
- Navigli, *Is Word Sense Disambiguation Dead in the LLM Era?* AAAI 2026 [arXiv](https://ojs.aaai.org/index.php/AAAI/article/download/41331/45292)
- Lesk 1986, *Automatic Sense Disambiguation Using Machine Readable Dictionaries* — 经典 Lesk 算法
- LANE, *Lexical Adversarial Negative Examples for WSD*, arXiv 2511.11234 (2025)

核心观点：
- WSD 是 NLP 最古老问题之一；Lesk 算法用**词典定义的词重叠**做消歧，零依赖、纯字符串。
- 即使在 LLM 时代，WSD 仍未"死亡"，因为 LLM 对非主导义项仍系统性误判。
- 中文 WSD 可用《同义词词林》或 HowNet 的义项定义做 Lesk-style 消歧。

**对项目的启示**：
- 项目已有 [scripts/weights/cilin_synonyms.json](file:///d:/working/0001/humanize-chinese-dimension/scripts/weights/cilin_synonyms.json)（哈工大同义词词林，38873 词），但只是当**同义词表**用，没做义项区分。
- 可以再内嵌一个**轻量义项定义词典**（JSON，每词 2–3 个义项 + 定义关键词），用 Lesk 算法在替换前判断候选词是否与上下文义项一致。
- 这是零依赖路径：纯字符串重叠计算。

### 2.5 Burstiness 与检测

**来源**:
- GPTZero / Tian 2023，burstiness + perplexity 双信号
- Church & Gale 1995, *Poisson Mixtures*，词频 burstiness 的统计学起源
- 2025 Nature portfolio *Humanities and Social Sciences Communications* stylometric study：AI 创意写作 burstiness 显著低于人类
- MDPI 2025 rapid review：**burstiness 是最可靠的机械信号**

核心观点：
- Burstiness = 句长方差 / 困惑度方差。AI 文本低 burstiness，人类高 burstiness。
- 人类写"短-长-短-特长-短"的节奏，AI 写等长句。
- **不能靠单插一句短句伪造 burstiness**，检测器看的是整篇分布。

**对项目的启示**：
- `burstiness_engineering` 的方向**对**，但实现方式有问题：它只在 15–25 字句里拆/合，且拆完插碎片，导致"细胞代谢、。真的。增殖"这种破坏语义的拆分。
- 正确做法：burstiness 应该通过**整篇句长分布的重新规划**实现，而非局部拆句。可以预设几种"人类节奏模板"（短-长-中-特长-短），按段落套用。
- 短句应当来自**原文已有的语义可分点**（如并列项、转折点），而不是外部碎片。

### 2.6 标点指纹

**来源**:
- Root Access 2026, *AI Has a Punctuation Addiction*：AI 用 em dash 频率比人类高 3–10 倍
- NetusAI stylometry：stylometry 分析 rhythm / cadence / punctuation
- 腾讯朱雀实测：标点转换（。→…… 等）能降检测率，但**不能完全去除 AI 痕迹**

核心观点：
- AI 文本标点**分布均匀**，人类标点**不规律**（三逗号连用后五句无逗号）。
- AI 滥用 em dash / 冒号 / 省略号制造"戏剧停顿"。
- 单纯标点替换是表层对抗，检测器仍能从中层特征（词汇搭配熵、句长方差、指代链）识别。

**对项目的启示**：
- `punctuation_humanize` 加省略号是"学 AI 滥用省略号"，方向可疑——人类在学术/公文里几乎不用省略号，硬加反而暴露。
- 标点人性化应该**模仿人类的标点不规律性**（逗号密度波动），而非模仿 AI 的省略号习惯。
- 省略号应当**只在原文有"未尽/沉思"语义时保留**，不应无中生有。

### 2.7 对抗式改写的质量权衡

**来源**:
- NeurIPS 2025, *Adversarial Paraphrasing: A Universal Attack for Humanizing AI-Generated Text* [NeurIPS](https://nips.cc/virtual/2025/loc/san-diego/oral/116833)
- AuthorMist, arXiv 2503.08716 (2025)
- IJRASET 2025, *Humanizing Text with AI*：强调 semantic awareness + 情感语气 + 非正式模式

核心观点：
- Adversarial Paraphrasing 在 RADAR / Fast-DetectGPT 上 T@1%F 降 64–99%，但论文承认 **"slight degradation in text quality"**。
- AuthorMist 用 3B 参数 LLM + GRPO 强化学习，才能把语义相似度维持在 0.94+。**纯规则方法没有这个能力**。
- IJRASET 2025 的 pipeline 包含 **semantic awareness 模块**，不是盲目扰动。

**对项目的启示**：
- 项目作为零 LLM 工具，**没有 LLM 兜底语义**，所以更不能走对抗攻击路线。
- 当前 Adaptive 路由把 LR 分当唯一 reward，相当于无语义约束的对抗攻击，质量损失比论文方法更大。
- 应当把"降分"从**硬目标**改为**软约束**：在语义保持阈值内才允许操作生效。

## 三、优化方向建议（零依赖 / 轻量词典）

下列每条建议都标注了**依赖性质**和**改动位置**，确保不引入 jieba 之外的重依赖。

### 3.1 短句注入：从"盲插"到"语境感知"

#### 方向 A：用话语标记语（DM）替代无实义碎片

**依赖**: 零（纯 JSON 词典）

把 `_FRAGMENTS` 拆成**按 discourse relation 分类**的 DM 词表，插入时根据与前句的关系选类：

```python
# 建议：scripts/weights/discourse_markers.json（新增，~2KB）
{
  "contrast": ["不过话说回来。", "换个角度看。", "话又说回来。"],
  "elaboration": ["说得更细点。", "具体讲。", "往深了说。"],
  "cause": ["这么看。", "顺着这思路。", "往这上靠。"],
  "hedge": ["未必如此。", "也难讲。", "不一定。"],
  "comment_neutral": ["看起来是这样。", "有这个说法。"]
}
```

插入规则：
- 默认只插 `hedge` 或 `comment_neutral`（语用最安全）。
- 只有当检测到前句有转折词（"但是""然而"）时才插 `contrast` 类。
- **情感/语体强约束**：若前句含怀念/温情/悼词词（"爷爷""母亲""回忆""记得"），禁插 `comment_neutral` 里的消极项（"没什么大不了的""算了"）。

#### 方向 B：中心理论约束（轻量实现）

**依赖**: 零（字符串规则）

Centering Theory 的简化实现：
1. 用 `jieba`（已有依赖）抽取每句的实体（名词）。
2. 相邻句若**无共享实体** → 判定为 Rough-shift → **禁止插碎片**（本来就不连贯，再加碎片更乱）。
3. 相邻句若**共享中心** → Continue → 可插 `elaboration` / `hedge` 类 DM。

这能避免案例 3"在这个世界上。谁知道呢。每个人都有自己的邻居"——"在这个世界上"和"每个人"中心不衔接，本就该合并，不该插碎片。

#### 方向 C：情感一致性检查（词典规则）

**依赖**: 零（情感词典 JSON）

新增 `scripts/weights/sentiment_lexicon.json`（~5KB，可从现有情感词典开源项目摘取），给 `_FRAGMENTS` 每条标情感极性：

```
"没什么大不了的" → negative_diminishing
"算了" → negative_resigned
"未必如此" → neutral_hedge
"看起来是这样" → neutral_comment
```

插入前检查前句情感：
- 前句 positive（怀念/赞美/希望）→ 禁插 negative 类。
- 前句 neutral / academic → 只允许 hedge / neutral_comment。
- 前句 negative → 可插 negative（但仍有频率上限）。

#### 方向 D：碎片位置硬约束

**依赖**: 零（字符串规则）

修复"细胞代谢、。真的。增殖"这种断词：
- `burstiness_engineering` 的 `_find_natural_split` 拆出的"前半段"若**末尾是顿号/逗号且后半段是并列项**（即拆点在并列结构内部），**禁止在拆点插碎片**。
- 碎片只能插在**完整句子之后**（句号/感叹号/问号后），不能插在逗号/顿号后。
- `fragment_injection` 第 208 行 `if len(sent) > 25` 改为 `if len(sent) > 25 and sent[-1] in '。！？'`。

### 3.2 标点人性化：从"机械添加"到"语境触发"

#### 方向 A：省略号语境触发

**依赖**: 零（触发词表）

省略号只在末句语义属于下列类时才允许加：
- 未尽列举：末句含"等""之类""比如""诸如此类"
- 沉思/不确定：末句含"或许""可能""也许""大概"
- 引文省略：末句是引号且未闭合

实现：把 `punctuation_humanize` 第 452 行的 `rng.random() < intensity * 0.3` 改为**先过语境词检查，再过随机概率**。

#### 方向 B：标点频率上限

**依赖**: 零

- 单篇省略号硬上限：**1 次**（人类学术写作省略号密度 ~0.5/千字）。
- 单篇感叹号硬上限：**2 次**（小红书风格例外，可放宽）。
- 已有 `punctuation_humanize` 第 452 行 `result.count('……') == 0` 是个开始，但只防重复，不限总量。改为 `result.count('……') < 1`。

#### 方向 C：逗号密度波动（替代省略号策略）

**依赖**: 零

与其加省略号，不如制造**逗号密度的不均匀**（这才是人类真实特征）：
- 在 30% 的段落里，把 2–3 个相邻长句的逗号**合并为句号**，制造"紧凑段"。
- 在另 30% 段落里保留长句，制造"舒缓段"。
- 这比省略号更像人类，且不破坏语义。

### 3.3 同义词替换：从"无 WSD"到"轻量 sense-aware"

#### 方向 A：Lesk-style 词义消歧

**依赖**: 零（内嵌义项定义 JSON）

新增 `scripts/weights/sense_definitions.json`（~50KB，可从 HowNet / 中文 WordNet 摘取高频多义词的 2–3 个义项），结构：

```json
{
  "数据": [
    {"sense": "data", "keywords": ["分析", "存储", "隐私", "集", "库", "采集"]},
    {"sense": "quantity", "keywords": ["数额", "多寡", "量", "统计", "数字"]}
  ]
}
```

替换前用 Lesk 算法：
1. 取目标词上下文 ±10 字。
2. 对每个候选义项，计算义项 keywords 与上下文词的重叠数。
3. 选重叠最高的义项；若候选替换词的 sense 与上下文 sense 不一致，**放弃替换**。

这能直接修复"数据隐私→数额隐私"：上下文有"隐私"，匹配"数据:data"义项，而"数额"属于"quantity"义项，不一致 → 不替换。

#### 方向 B：领域术语保护词典（白名单）

**依赖**: 零（JSON）

新增 `scripts/weights/protected_terms.json`（~10KB），按领域分组：
- 医学：PKM2 / 丙酮酸激酶 / 凋亡 / 糖酵解 / 信号通路
- 法律：构成要件 / 数据隐私 / 算法偏见
- 学术：BERT / Transformer / 微调 / 预训练

替换时若目标词在白名单，**跳过**。已有 `academic_cn.py` 的"学术词表禁用口语候选"是类似思路，但需要泛化到通用 humanize。

#### 方向 C：搭配约束（collocation）

**依赖**: 零（搭配词典 JSON）

新增 `scripts/weights/collocations.json`（~20KB），记录高频搭配：
```
"数据" + "隐私/安全/分析/集/库" → 合法
"数额" + "巨大/微小/具体" → 合法
"数额" + "隐私" → 非法
```

替换时检查替换词与相邻词的搭配合法性。这是简化版 WSD，比 Lesk 更快但覆盖窄。

### 3.4 语义保持：引入轻量语义相似度度量

#### 方向 A：关键词保留率（keyword retention）

**依赖**: jieba（已有）

在 `best-of-n` 候选筛选时加入约束：
1. 用 jieba 抽取原文 Top-K 关键词（TF-IDF，已有 `ngram_model.py` 可复用）。
2. 候选改写若**关键词保留率 < 70%**，直接丢弃，不论 LR 分多低。
3. 这能防止"数据隐私"类关键术语被换掉。

#### 方向 B：句对齐语义相似度（轻量）

**依赖**: 零（字符 n-gram + 词林）

不用 BERTScore（需要 BERT），改用**轻量句对齐**：
1. 原文与候选按句对齐（已有 `split_sentences`）。
2. 每对句算：字符 2-gram Jaccard + 词林同义覆盖率。
3. 平均相似度 < 0.6 的候选丢弃。

精度不如 BERTScore，但**零依赖**，且能捕捉"数额隐私"这类字符重叠高但词林不同义的 case（"数据"和"数额"在词林里不同类）。

#### 方向 C：语义保持作为 best-of-n 的硬过滤

**依赖**: 零

当前 `best-of-n` 排序（[scripts/humanize_cn.py](file:///d:/working/0001/humanize-chinese-dimension/scripts/humanize_cn.py) 第 3902 行附近的 final verification loop）只看 perplexity。建议改为**两阶段**：
1. **硬过滤**：语义相似度 / 关键词保留率低于阈值的候选直接丢。
2. **软排序**：通过过滤的候选按 LR 分排序。

这把"降分"从唯一目标变成"在语义安全的前提下降分"。

### 3.6 自适应强度校准

#### 方向 A：把 LR 分从硬目标改为软约束

**依赖**: 零

当前 [dimension_router.py](file:///d:/working/0001/humanize-chinese-dimension/scripts/dimension_router.py) 的路由逻辑是"哪个维度高就强制降哪个"。建议改为：
1. 每个操作带**预估语义代价**（基于 A/B 测试统计）。
2. 路由时在"语义代价预算"内选操作组合，而非无脑全开。
3. `humanize_cn.py` 第 3847 行 `_ro_params[_op_name] = max(_route_val, _ro_defaults[_op_name])` 的"强制不低于 0.3"应当改为"在语义预算内自适应"。

#### 方向 B：短文本/长文本独立策略

**依赖**: 零

PR 第 7 条指出短文本（< 200 字）操作空间小。建议：
- 短文本：只做**词汇层**操作（vocab scrub + hedging），不做**结构层**操作（burstiness / fragment），避免结构操作把短文本拆得更碎。
- 长文本：放开结构层操作，但加段落保留约束（已有 `\n\n` 分段处理）。

#### 方向 C：A/B 测试系统校准

**依赖**: 零（复用 `dev/ablation_runner.py`）

PR 第 6 条提到操作-效应系数是经验估计。建议：
1. 用 `dev/ablation_runner.py` 跑每个操作的单独 ablation。
2. 记录每个操作对 LR 分的**实际降幅**和对语义相似度的**实际代价**。
3. 用实际数据替换 `scripts/weights/dimension_weights.json` 里的经验系数。

## 五、关键约束再强调

1. **零外部依赖**：除 jieba 外不引入任何 pip 包。所有新词典以 JSON 形式内嵌 `scripts/weights/`。
2. **语义优先**：降分是软目标，语义保持是硬约束。`best-of-n` 必须先过语义过滤再排 LR 分。
3. **反对攻击式改写**：不把检测器当 oracle 做对抗。目标是"更像人写的"，不是"骗过检测器"。
4. **每个操作带安全边界**：语境触发 + 频率上限 + 情感/语体一致性。
5. **可复现**：所有阈值在 HC3-Chinese 对照样本上校准，不用拍脑袋。
