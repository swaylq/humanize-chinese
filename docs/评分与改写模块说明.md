## 一、核心概念：评分是怎么来的

### 这不是一个"AI 概率"分数

很多人以为这个 0-100 分表示"AI 生成的概率"，但它的实际含义是：

> **这段文本在多大程度上展示了 AI 写作的特征模式。**

0 分 = 几乎没有任何 AI 写作特征，25 分 = 有点痕迹，50 分 = 明显痕迹，75+ 分 = 几乎可以肯定有 AI 参与。

### 分数的构成

最终的分数由两层组合而成：

```
最终分数 = 规则层分数(占20%) + 统计模型分数(占80%)
```

| 层级 | 权重 | 看什么 | 像什么 |
|------|------|--------|--------|
| **规则层** | 20% | 具体的词汇、句式、结构模式 | 像一份"AI写作痕迹检查清单" |
| **统计模型层** | 80% | 22-25 个连续数值特征的数学组合 | 像一个训练过的"AI风格嗅觉" |

#### 为什么统计模型占 80%？

因为规则层单独使用时，区分力只有 73%（100 对 AI/人类文本随机抽取一对，检测器给更高分的概率），加上统计模型后达到 95.5%。统计模型能捕捉规则无法表达的"微妙肌理"——比如句子长度的整体变化节奏。

## 二、检测模块：它到底在看什么

### 输入 → 输出

```
输入：一段中文文本（可以是 50 字的短问答，也可以是 3000 字的长篇小说章节）
  ↓
检测引擎分析
  ↓
输出：0-100 分数 + 等级 + 可疑句子列表 + 各维度详细报告
```

### 两层检测各看什么

#### 规则层（20+ 个维度）

这是一个"AI 写作特征清单"。扫描文本中是否出现了以下模式：

| 类别 | 严重度 | 示例 |
|------|--------|------|
| 🔴 三段式套路 | 高危 | "首先…其次…最后" |
| 🔴 机械连接词 | 高危 | "值得注意的是" "综上所述" "不难发现" |
| 🔴 空洞宏大词 | 高危 | "赋能" "闭环" "数字化转型" "深度协同" |
| 🟠 AI 高频词 | 中危 | "助力" "彰显" "底层逻辑" "抓手" "复盘" |
| 🟠 模板句式 | 中危 | "随着…的不断发展" "在当今…时代" |
| 🟠 填充废话 | 中危 | "值得一提的是" "众所周知" "毫无疑问" |
| 🟡 过度谨慎 | 低危 | "在一定程度上" 出现超过 5 次 |
| 🟡 列举上瘾 | 低危 | 频繁使用 ①②③ 或 bullet 列表 |
| 🟡 标点过度 | 低危 | 破折号占比 >1%、分号占比 >0.5% |
| ⚪ 段落均匀 | 风格 | 每段长度几乎一样 |
| ⚪ 节奏单一 | 风格 | 每句话差不多长 |
| ⚪ 情感平淡 | 风格 | 全文几乎没有情感词或个人表达 |
| ⚪ 句首重复 | 风格 | "本文"开头出现了 3+ 次 |

每种模式命中后会根据严重程度累计加分，但规则层总分上限为 60 分。

#### 统计层（17 个数值信号）

统计层不检查"有没有某个词"，而是计算文本的数值特征。每个特征都有一个基于 HC3 数据集（12,853 对真实人类 vs ChatGPT 问答）校准的阈值。

| 信号 | 衡量什么 | AI 文本的典型值 | 人类文本的典型值 | 你在改写时应该怎么理解 |
|------|---------|---------------|----------------|---------------------|
| **句长变异系数** | 句子长度是否参差不齐 | CV ≈ 0.32（句句差不多长） | CV ≈ 0.52（有长有短） | AI 喜欢写 15-25 字的"舒适区"句子，打破这个节奏降分最有效 |
| **短句占比** | <10 字的短句有多少 | 约 2.6%（几乎没有短句） | 约 25%（四分之一是短句） | 人类说话经常蹦短句，AI 很少 |
| **GLTR 续接分布** | 每个字后面选的词是否"安全" | 21%+ 的字选了最可能的下一个字 | 更分散，经常选冷门字 | AI 倾向于选最高概率的续接，人类会偶尔"偏一下" |
| **DivEye 惊奇度偏度** | 用字的"惊喜程度"分布形态 | 偏度 < 1.35（平整无波澜） | 更高（偶尔出人意料） | 人类写作有高低起伏的用词趣味 |
| **DivEye 惊奇度峰度** | 同上的"尖峰"程度 | 峰度 < 0.35 | 更高 | |
| **困惑度** | 字序列有多"可预测" | 偏低 | 正常范围 | AI 的字序列比人类更"光滑"、更可预测 |
| **逗号密度** | 每百字多少个逗号 | 约 3.8 | 约 5.3 | HC3 上反而是人类逗号更多（日常对话停顿多） |
| **过渡词密度** | "然而""此外""因此"等频率 | > 8 次/千字 | ≤ 8 | AI 太爱用逻辑连接词 |
| **局部曲率** | 滑动窗口困惑度变化 | > 0.9 | ≤ 0.9 | AI 每处选词都"贪心"地选最强的 |
| **Binoculars 分值** | 文本风格偏离人类语料的程度 | 偏近"平均中文" | 偏离更大 | AI 的文体落在语料库均值附近，人类更有个人风格 |
| **字符多样性 MATTR** | 用字重复程度 | < 0.65（字比较集中） | ≥ 0.65 | |
| **段内句长 CV**（仅长文本） | 同一段内句子是否等长 | 均值 0.29 | 均值 0.49 | 每一段内部的句子也有节奏变化 |
| **段落长度 CV**（仅长文本） | 各段长度是否差不多 | CV 0.36 | CV 0.74 | AI 的文章段落像"切好的豆腐块" |
| **跨段 trigram 重复**（仅长文本） | 不同段落重复使用相同的 3-字短语 | 更高 | 更低 | AI 容易在不同段复用同一短语 |
| **首尾段重叠率**（v6 ToW） | 首段和末段用词的重叠程度 | Jaccard > 40%（"总结式"结尾） | < 40%（用词有变化） | AI 末段喜欢机械复述首段的词语 |
| **末句模板化**（v6 ToW） | 最后一句话是不是模板 | "综上所述""总而言之"等 | 自然收尾 | AI 容易在末句套模板 |
| **情感词分布CV**（v6 ToW） | 情感词是否均匀分布在每段 | CV < 0.5（每段撒一点） | CV 高（聚集在一两段） | 人类情感表达是聚集的，AI 是均匀撒的 |

### 最终分数对应表

| 分数 | 等级 | 含义 |
|------|------|------|
| 0-24 | 低 | 基本像人写的，看不出明显 AI 痕迹 |
| 25-49 | 中 | 有些 AI 味，但整体还算自然 |
| 50-74 | 高 | 不少人读着会觉得"这像 AI 写的" |
| 75-100 | 极高 | 几乎确定是 AI 生成，痕迹非常明显 |

## 三、改写模块：它到底改了什么

### 输入 → 输出

```
输入：一段 AI 味的中文文本
  ↓
改写流水线（多个策略依次执行）
  ↓
输出：AI 味降低的中文文本（best-of-N 选最优）
```

### 改写流水线的五个阶段

```
原始文本
  │
  ├── 阶段 1：短语替换（基础去 AI 味）
  │   把 "值得注意的是" → "注意" / "要提醒的是"
  │   把 "赋能" → "帮助" / "支持"
  │   共 165 条替换规则，来自配置文件
  │
  ├── 阶段 2：同义词替换（打破用词惯性）
  │   把频繁重复的词换成同义词
  │   "进行" → "开展" / "实施" / "做"
  │   困惑度引导选词：选"次自然"的候选项（最自然的往往是 AI 最爱的）
  │   可选启用 CiLin 同义词词林扩展（38,873 条）
  │
  ├── 阶段 3：句式重建（打破模板结构）
  │   15+ 种句式变换模板
  │   "通过X，Y能够Z" → "Y Z，靠的是X"
  │   "X不仅A，还B" → "X A。同时也B"
  │   长句拆分 + 短句合并
  │
  ├── 阶段 4：噪声注入（加入"人味"信号）
  │   在段落末追加短评价句："成效不小。" "颇有看点。"（仅当段落含正向内容标记）
  │   在句首插入过渡口语："说实话，" "其实，"
  │   句长随机化：刻意制造长短交错
  │   注意：这个阶段默认只在"AI 分数≥25"时触发
  │
  └── 阶段 5：best-of-N 择优
      对同一输入生成 N=10 个候选改写（使用不同随机种子）
      用评分模块对每个候选打分
      选分数最低（最像人）的那个作为最终输出
```

### 改写强度的自动调节

改写不是"大力出奇迹"——会根据输入文本的 AI 分数自动选择三档策略：

| 档位 | 触发条件 | 做什么 | 设计意图 |
|------|---------|--------|---------|
| **保守** | 原文分数 < 5 | 仅做短语替换 + 标点清理 | 文本已经很干净，别乱动 |
| **适中** | 5 ≤ 分数 < 25 | +句式重建 + 同义词替换 | 有些痕迹，适度打磨 |
| **全力** | 分数 ≥ 25 | 全部策略（含噪声注入 + 句长随机化） | 明显 AI 文本，全面改写 |

### 各个改写策略的设计意图

#### 阶段 1：短语替换（目标：消灭规则层的明显信号）

- **针对什么**：规则层中 🔴 高危和 🟠 中危的检测词
- **怎么做**：直接替换或删除 AI 套话词汇
- **举例**："综上所述，人工智能技术具有重要价值" → "总之，人工智能技术有重要价值"
- **降分效果**：直接消除规则层的 3-15 个 hit point

#### 阶段 2：同义词替换（目标：降低统计层的"可预测性"）

- **针对什么**：统计层的困惑度信号（字序列太可预测）
- **怎么做**：用次高频的同义词替换高频重复词。选词算法是"困惑度引导"——计算每个候选替换后的困惑度，选**次高**的（最高的往往是古语或错字，次高的是人类自然的用词变化）
- **举例**："系统能够分析数据并推动发展" → "架构可以解读信息并驱动推进"
- **降分效果**：提升困惑度，降低 GLTR top-10 占比

#### 阶段 3：句式重建（目标：打破模板句式）

- **针对什么**：规则层的模板句式和统计层的句长均匀性问题
- **怎么做**：用正则匹配识别 AI 常见句式，用结构模板改写
- **降分效果**：提升 sent_len_cv，降低 equal_mid_frac

#### 阶段 4：噪声注入（目标：修复"人类写作的统计特征"）

- **针对什么**：统计层的短句占比和句长变异系数——两个最强的单信号（Cohen's d = 1.21 / 1.22）
- **怎么做**：在合适位置插入短评价句和过渡口语
- **降分效果**：直接消除规则层 12+14 分的 stat 权重
- **注意**：这个策略是"信号逆向工程"——不是为了文本质量，而是为了骗过检测器。如果你的目标是文本质量而非过检测，可以考虑关掉（`--no-noise`）

#### 阶段 5：best-of-N（目标：找到"局部最优"）

- **为什么需要**：改写有随机性（同义词选择、噪声插入位置都是随机的），不同随机种子产生不同候选
- **怎么做**：生成 N=10 个候选，用评分模块打分，选分最低的
- **效果**：单一候选的降分效果约 30-40 分，best-of-10 可额外提升 10-15 分
- **v6 增强**：当候选输出长度超出原始文本 30% 时自动加罚分，抑制改写膨胀（基于 ToW 论文"Longer is NOT Better"发现）

#### v6 ToW 增强策略（需 `--enable-v6` 开启）

| 策略 | 针对什么 | 怎么做 | 设计依据 |
|------|---------|--------|---------|
| **聚集式情感注入** | 情感词均匀分布（AI特征）| 选1-2个内容密度最低的段落集中注入情感词，其余段落不加 | ToW 论文：人类情感表达聚集、AI 均匀撒 |
| **首尾段落浅改写** | 首尾段过度改写导致逻辑断裂 | 学术/正式场景下，首2段+末2段仅做短语替换，跳过句式重建和噪声注入 | ToW 论文：Opening-Ending 是跨体裁稳定评估维度 |
| **长度罚分** | 改写导致文本恶性膨胀 | best-of-N 评分中对超出原长30%的候选加罚分 | ToW 论文：输入长度与 Content 分负相关（ρ=-0.44） |

## 四、两者的关系：改写如何影响评分

### 数学上精确的因果关系

| 改写操作 | 影响的评分信号 | 规则层变化 | LR 层变化 | 综合 fused 分变化 |
|---------|--------------|-----------|----------|------------------|
| 替换 AI 套话词 | mechanical_connectors, empty_grand_words | -3~15 分 | 微小 | **-3~12 分** |
| 打破三段式结构 | three_part_structure | -8 分/处 | — | **-1.6 分** |
| 拆分舒适区句子 | sent_len_cv ↑, equal_mid_frac ↓ | -14 分 | coef -1.752 | **~19-32 分** |
| 插入短句 | short_frac ↑ | -12 分 | coef +0.374 (弱) | **~5 分** |
| 合并短句对 | sent_len_cv ↑ | -14 分 | coef -1.752 | **~15 分** |
| 增加逗号 | comma_density ↑ | -8 分 | 微小 | **~2 分** |

**最重要的发现**：句长多样化的降分效果（19-32 分）远大于单纯塞短句（~5 分）。因为句长变异系数同时在规则层（权重 14）和 LR 层（系数 -1.752，是 22 个特征中最强的）起作用。

### 为什么 best-of-N 有效

同一个输入，10 次改写之间的分数差距典型是 10-20 分。因为每次改写：
- 同义词选择是不同的 2-3 个候选项中随机挑
- 噪声插入位置和内容不同
- 句式变换的概率触发不同

这些随机性的叠加导致输出分数有显著波动，best-of-N 策略抓住了这个波动，选了最低的那个。

## 五、场景差异：通用、学术、长文本有什么不同

### 三个场景的检测模型不同

| 场景 | 检测模型 | 训练数据 | 特殊特征 |
|------|---------|---------|---------|
| **通用** (default) | 多源 LR (lr_coef_cn.json) | HC3 问答 + CUDRT 新闻 + 长文本，共 1022 条 | 22 维 |
| **学术** (academic) | 学术 LR (lr_coef_academic.json) | 维基百科学术语域 vs HC3 ChatGPT，共 640 条 | 22 维，但训练语域不同 |
| **长文本** (novel/auto) | 长文本 LR (lr_coef_longform.json) | AI 长文 + 人类小说 + 人类新闻，共 272 条 | 25 维（多了段落级特征） |

### 三个场景的改写策略不同

| 操作 | 通用 | 学术 | 长文本 |
|------|------|------|--------|
| 同义词替换 | 全量 ~150 组同义词 | 过滤掉 30 个口语候选词 | 过滤掉部分口语词但保留小说可用的 |
| 噪声注入 | 混合类别的短句/过渡语 | 仅学术类别的含蓄表达 | 跳过 filler/personal 类别 |
| 短句追加 | 12 条"成效不小"等 | 18 条正式语体"诚然如此"等 | 与通用相同 |
| 段落级操作 | 无 | 无 | 有（段落 CV 调整、跨段 trigram 去重） |

### 为什么学术场景特殊

学术论文的改写约束最多：
- **不能口语化**：不能把"研究"改成"琢磨"，不能把"具有"改成"有了"
- **术语保护**：17 个核心学术词（如"研究""分析""系统""变量"）禁止替换
- **不能插入短评**：段末加"颇有看点"在学术论文中很突兀，改用正式语体池

这是为什么学术场景的降分上限比通用低（约 65 分 vs 83 分）——不是检测器对学术更严，而是改写空间更小。

### 为什么长文本需要专门的模型

短问答（HC3 数据集，平均 200 字）的句长特征和长文章（小说/博客/学术论文，平均 1500+ 字）不同：

- 短文中，CV=0.32 可能就是 AI
- 长文中，CV=0.55 都可能是 AI（长文天然有更多句长波动）
- 长文还有短文没有的段落级特征：段落长度均匀度、段内句长 CV、跨段短语重复

因此系统用"≥1500 中文字"作为切换标记，自动使用长文本模型。
